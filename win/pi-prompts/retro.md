지금까지의 이 세션을 돌아보고, 다음 세션에도 남겨야 할 것만 추려라. 초점이 주어졌으면 그것부터: $ARGUMENTS

규칙:
- 파일을 쓰거나 고치지 마라. 이번 응답은 제안만 한다. 사용자가 항목 번호로 승인하면 그때 반영한다.
- 이 세션에서 실제로 확인된 것만 쓴다. 추측·일반론·이미 AGENTS.md에 있는 내용은 빼라.
- 틀렸다가 고친 것은 "처음 시도 → 실패 이유 → 통한 방법" 순서로 한 줄에 쓴다.

출력 형식:

## 1. AGENTS.md 추가안
프로젝트 규칙(명령, 경로, 빌드·테스트 방법, 금지사항)은 작업 폴더의 `AGENTS.md`, 모든 프로젝트에 통하는 습관은 `C:\pi_agent\home\agent\AGENTS.md` 대상으로 나눠, 추가할 줄을 그대로 적어라. 항목마다 번호와 근거(이 세션의 어느 장면인지)를 붙여라.

## 2. 버릴 것
이 세션에서 모델이 반복한 실수나 쓸모없던 시도. 규칙으로 막을 수 있으면 1번에 넣고, 아니면 여기 적어라.

## 3. LoRA 학습 후보 여부
이 세션을 LoRA 학습 데이터로 승인할 만한지 "예/아니오 + 한 줄 이유"로 답하라. 기준: 최종 결과가 맞았고, 사용자가 받아들였고, 중간의 잘못된 도구 호출이 결과를 오염시키지 않았다. 비밀번호·키·개인정보가 오갔으면 아니오. 예라면 `/session` 으로 세션 ID를 확인해 `C:\pi_agent\lora\approved.txt` 에 한 줄로 넣으라고 안내하라.
